2. Root Cause Analysis

Primary Suspected Cause (High Likelihood)
MLO Peer Context Corruption During SAE Exchange
The AP loses the peer node context (ni becomes NULL) between SAE Commit and
Confirm phases, causing:
1. SAE verifier calculation mismatch
2. Frame transmission failure when sending Auth response
3. Inability to complete authentication
Why this matches [[Knowledge: WIN_Connectivity Issues - Wifi Debug
handbook|section:4. Authentication|context:SAE exchange fail case with Confirm
mismatch indicates cryptographic material inconsistency between exchanges]]:
SAE Confirm verifier mismatch occurs when peer state is inconsistent
The calculated verifier ab 95 67 06... doesn't match received de e8 71 a8...
State transition "Committed -> Nothing" indicates peer context reset
Alternative Hypothesis (Medium Likelihood)
Driver/Firmware MLO State Synchronization Issue
The MLO link management loses synchronization between hostapd and driver:
DEL_STATION called prematurely during active SAE exchange
Driver reports "ni is NULL" when hostapd still expects peer to exist
Timing race condition in MLO peer creation/deletion
Lower Likelihood Cause
SAE Password/Configuration Mismatch
Less likely given that SAE Commit phase succeeds and PMK is derived successfully.
