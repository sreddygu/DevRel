# P3 Project Onboarding

1. Read the project README and existing project-local skill catalog first.
2. Record only demonstrated capabilities, public prerequisites, supported
   targets, and known exclusions. Do not turn a narrative target into a product
   claim.
3. Select the smallest delivery lane from `references/P3_DELIVERY_MODELS.md`: source skill
   pack, installable starter kit, or device-ready release kit.
4. Name the next bounded project-local skills. Reuse shared P3 skills rather
   than copying their procedure.
5. Add an owner, review cadence, validation evidence, and public feedback path
   before proposing promotion beyond `incubating`.

Stop and report a gap when public source, public dependencies, or a reproducible
validation path is absent. Never require internal accounts, private networks, or
undocumented tooling for P3 use.
